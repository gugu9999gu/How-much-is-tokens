# v1.0.32 — Generative-media MCP + multi-account

## 목표

생성형 미디어 공급자의 단일 API credential 모델을 프로필 모델로 확장하고, 공급자가 공식 hosted MCP를 제공하는 경우 MCP의 quota/balance tool을 사용해 잔여량을 표시한다.

## 공급자별 경로

| Provider | 추가 API 계정 | 공식 MCP | MCP 인증 | 잔여량 전략 |
|---|---|---|---|---|
| fal.ai | 지원 | `https://mcp.fal.ai/mcp` | Bearer API Key | MCP 우선, 기존 billing REST fallback |
| Higgsfield | 지원 | `https://mcp.higgsfield.ai/mcp` | OAuth | MCP balance/credits 우선 |
| Magnific | 지원 | `https://mcp.magnific.com` | OAuth | MCP 호환 balance tool 우선, 기존 activity REST fallback |
| ElevenLabs | 지원 | `https://api.elevenlabs.io/v1/mcp` | OAuth | MCP subscription/usage tool 우선, subscription REST fallback |
| Stability AI | 지원 | 공식 잔액 MCP 미확인 | - | 기존 `/v1/user/balance` API |

공식 MCP가 존재한다는 사실과 그 MCP가 반드시 잔액 tool을 제공한다는 사실을 구분한다. MCP 연결은 성공했지만 quota tool이 없거나 응답을 해석할 수 없으면 숫자를 추측하지 않는다.

## 데이터 모델

`settings.mediaProviderProfiles`는 비민감 메타데이터만 저장한다.

- providerId
- profile id
- label
- mode: `api` 또는 `mcp`
- priority
- enabled

실제 credential은 `secrets.json`의 `mediaProfile:<provider>:<profile>:<field>` namespace에서 Electron `safeStorage`로 암호화한다.

MCP OAuth 상태도 동일 namespace에 암호화한다.

- oauthTokens
- oauthClientInformation
- oauthCodeVerifier
- oauthDiscovery

## MCP 보안 경계

- MCP endpoint는 코드에 등록된 공식 endpoint만 허용한다.
- renderer는 raw API Key/OAuth token을 읽을 수 없다.
- OAuth redirect는 임시 `127.0.0.1` loopback callback을 사용하고 state를 검증한다.
- MCP tool은 입력이 필요 없는 quota/balance 후보만 자동 호출한다. 임의 required argument를 추측해 호출하지 않는다.
- 응답에서 잔액을 확인할 수 없으면 숫자를 생성하지 않는다.

## 호환성

기존 provider-level API credential은 그대로 `기본 연결`로 조회한다. 추가 프로필만 새 media-profile namespace를 사용하므로 v1.0.31 이하 사용자는 키를 다시 입력하지 않아도 된다.
