# v1.0.24 — OpenRouter secure multi-key localhost router

## 목표

OpenRouter API Key를 여러 개 등록해 각 key의 사용량/credit 상태를 독립적으로 보고, 로컬 OpenAI-compatible client가 한 개의 localhost endpoint를 사용하면서 사용 가능한 key로 안전하게 failover할 수 있게 한다.

이 기능은 OpenRouter API credential만 다룬다. ChatGPT/Codex 구독 로그인이나 CLI OAuth/session을 일반 API Key로 변환하거나 재사용하지 않는다.

## OpenRouter key profile

설정 → API 공급자 → OpenRouter에서 최대 16개의 key profile metadata를 등록할 수 있다.

형식:

```text
primary|주 키|10|on
backup|백업 키|20|on
```

- `id`: 영문 소문자/숫자/underscore/hyphen, 최대 32자
- `label`: UI 표시 이름
- `priority`: 낮을수록 우선
- `on/off`: 라우팅 및 usage 조회 활성화 여부

각 profile의 API Key/Management Key 원문은 profile metadata와 분리한다.

- secret key namespace: `openrouterProfile:<id>:apiKey`, `openrouterProfile:<id>:managementKey`
- Electron `safeStorage` 암호문만 `secrets.json`에 기록
- `settings.json`에는 profile metadata와 configured boolean만 기록
- profile을 제거하면 해당 profile ciphertext도 prune
- 기존 v1.0.23 single OpenRouter API/Management Key는 `default` profile로 호환/migration
- OS secure storage를 사용할 수 없으면 plaintext fallback을 하지 않음

## localhost API Router

기본 endpoint:

```text
http://127.0.0.1:43123/v1
```

라우터는 `127.0.0.1` IPv4 loopback에만 bind한다. `0.0.0.0`, LAN, WAN, IPv6 wildcard에는 bind하지 않는다.

OpenAI-compatible client에는 OpenRouter 원본 API Key 대신 위젯에서 복사한 **별도 local Bearer token**을 사용한다.

예시 개념:

```text
Base URL = http://127.0.0.1:43123/v1
API Key  = <위젯에서 복사한 local Bearer token>
```

local token은 CSPRNG 32-byte 값으로 생성하고 safeStorage에 저장한다. renderer에 raw token getter를 노출하지 않고 main process가 OS clipboard에 직접 복사한다.

## 요청 보안 경계

- local request의 `Authorization`은 localhost 인증에만 사용
- upstream 요청 전 선택된 OpenRouter API Key로 `Authorization: Bearer ...`를 교체
- client `authorization`, `x-api-key`, `api-key`, OpenAI key header, cookie, hop-by-hop header를 upstream에 전달하지 않음
- request body/Authorization/raw API Key를 console에 기록하지 않음
- `/v1` 이외의 proxy path는 거부
- request body는 최대 10 MiB
- unauthenticated `/health`는 `ok/running`만 반환하고 profile/key 수를 노출하지 않음

## key 선택 및 failover

### priority-fallback

priority가 낮은 active profile부터 시도한다.

### max-remaining

위젯이 마지막으로 관측한 profile별 remaining metric이 있으면 높은 값을 우선한다. metric이 없는 profile은 priority 순서로 fallback한다.

### cooldown

upstream 응답을 client에 commit하기 전 다음 경우 다른 profile을 시도한다.

- network failure: 짧은 cooldown
- `401`, `402`, `403`: credential/account 상태 cooldown
- `429`: `Retry-After`를 우선 반영한 cooldown

모든 active key가 없거나 cooldown/실패 상태면 명시적 `503`으로 fail-closed 한다.

## streaming replay 방지

upstream이 정상 status를 반환하고 body를 client에 전달하기 시작한 시점부터 요청은 해당 profile에 commit된 것으로 본다.

이후 stream이 실패해도 다른 API Key로 같은 요청을 자동 재전송하지 않는다. 이는 중복 과금, 중복 tool call/side effect, 중복 completion을 방지하기 위한 경계다.

## Electron integration

Main process:

- router lifecycle 시작/중지
- profile secret 저장/삭제
- local token clipboard copy
- sanitized router status/metrics IPC

Preload:

- raw secret을 반환하지 않는 제한된 API만 노출
- usage payload에서 OpenRouter profile의 remaining/status metadata만 main router에 전달

Renderer:

- profile metadata 편집
- 선택 profile key 저장/삭제
- router enable/port/policy
- endpoint/status 표시
- local Bearer token clipboard copy
