# v1.0.21

## Codex / Work 자동 리셋

설정 → 자동화 → **Codex 한도 자동 리셋**에서 켤 수 있습니다. 기본값은 꺼짐입니다.

자동 사용 조건은 모두 충족되어야 합니다.

- 공식 `codex app-server`의 `account/rateLimits/read`가 실제 `rate_limit_reached`를 반환
- 사용 가능한 banked reset이 1개 이상 존재
- 사용자가 자동 리셋을 명시적으로 활성화
- 같은 quota reset epoch에서 아직 성공한 자동 사용이 없음

가장 먼저 만료되는 `available` 티켓을 선택하고 `account/rateLimitResetCredit/consume`을 호출합니다. 요청마다 idempotency key를 사용하며, 불확실한 네트워크 실패를 재시도할 때도 같은 key를 재사용합니다. 성공 후 rate limit과 usage를 다시 읽어 화면을 갱신합니다.

단순히 UI가 0%로 보이거나 stale cache가 남아 있는 것만으로는 티켓을 사용하지 않습니다. 설정값 초기화 시 자동 리셋은 다시 OFF가 됩니다.

## 크레딧 / 잔액

Provider 응답이 실제 잔액/한도를 제공하는 경우에만 카드에 별도 balance row를 표시합니다.

- Codex / Work: 보유 credits, monthly credit limit
- Claude: Usage Credits / spend limit
- Cursor: 포함 credits, on-demand, team pooled/on-demand
- Grok: prepaid balance, on-demand cap/usage
- Grok Bot: Cursor billing의 on-demand balance
- OpenRouter: account credits, API-key spending cap
- GitHub Copilot: premium request entitlement/remaining (금액이 아니라 `요청` 단위)
- Antigravity: 별도 monetary credit API가 확인되지 않아 quota만 표시

금액이 아닌 단위를 USD로 추정하지 않습니다. 없는 credit field도 만들지 않습니다. stale monetary balance는 최대 24시간까지만 재사용하며 OpenRouter는 기존 15분 제한을 유지합니다.

## Claude Fable / scoped quota

현재 Claude usage API의 `limits[]`를 우선 사용합니다. `kind=weekly_scoped`에 `scope.model.display_name`이 있으면 모델별 quota를 독립적으로 표시합니다.

예:

- 5시간/세션 한도
- 전체 주간 한도
- Fable 주간 한도
- 향후 추가되는 다른 named model의 주간 한도

호환 payload의 `seven_day_overage_included`도 Fable로 처리합니다. 반면 임의의 `seven_day_*` 내부 codename을 모델명으로 추측하지 않습니다.

## 다계정 기반

Provider/account 조합을 raw 계정 ID가 아닌 SHA-256 기반 `accountKey`로 구분합니다. persistent usage/credit cache와 Codex 자동화 상태가 계정별로 분리됩니다. raw account ID나 OAuth token은 이 cache에 저장하지 않습니다.

v1.0.21은 **다계정 데이터 모델 기반까지** 포함하며, 여러 격리 로그인 프로필을 동시에 등록하고 한도 도달 시 다른 계정 프로필로 실행을 자동 라우팅하는 기능은 후속 버전 범위입니다.
