# v1.0.31 — Complete account automation

v1.0.31은 v1.0.30 이후 남아 있던 계정 자동화와 CLI 유지보수 범위를 확장한다.

## 리셋 시점 표시

설정의 리셋 시간 표시는 세 가지 모드를 지원한다.

- `자동`: 남은 시간과 예정 일시를 5초마다 교대
- `남은 시간`: 카운트다운으로 고정
- `예정 일시`: 실제 리셋 날짜/시간으로 고정

## 다계정 연결

격리된 추가 계정:

- Codex — `CODEX_HOME`
- Claude — `CLAUDE_CONFIG_DIR`
- Grok — `GROK_HOME`
- Cursor — `CURSOR_CONFIG_DIR`
- Copilot — 격리된 `GH_CONFIG_DIR`; 실행 시 해당 GitHub OAuth 토큰을 `COPILOT_GITHUB_TOKEN`으로 프로세스 메모리에만 전달하고 `COPILOT_HOME`도 계정별로 분리

Grok Bot은 Cursor 인증을 공유하므로 Cursor 추가 프로필을 그대로 사용한다.

OpenRouter는 기존 secure OAuth/API-key profile 방식을 계속 사용한다.

동일한 실제 인증 계정으로 추가 로그인하면 fresh verified account identity를 기준으로 중복 프로필을 제거한다. stale cache나 단순히 quota 값이 같다는 이유로 계정을 합치지 않는다.

## Antigravity 다계정

공식 `agy`는 Windows Credential Manager의 단일 active credential을 사용한다. 위젯이 OAuth 파일을 복사하거나 credential store를 직접 덮어쓰지 않는다.

다계정이 필요한 경우 선택적으로 `github.com/shyim/agm`을 사용한다. 런타임 설치는 검토한 commit에 고정하며 `@latest`를 설치하지 않는다. `agm`은 자체 암호화 계정 저장소를 사용하고 선택 계정을 공식 `agy` credential store에 적용한다.

- `agm`이 없으면 기존 `agy` 단일 계정 기능은 그대로 동작
- Go가 설치되어 있으면 설정에서 고정 버전 계정 도우미 설치 가능
- `+ 계정`은 `agm login` 브라우저 OAuth 실행
- 연결 해제는 해당 `agm` 계정만 제거
- 사용량 cache에는 Antigravity 이메일/OAuth token 원문을 기록하지 않음
- standalone routing은 cache의 해시 account key와 실행 시점 `agm list`를 대조해 계정을 찾음

## Smart Routing

새 CLI 실행 계정 자동 선택 대상:

- Codex
- Claude
- Grok
- Cursor
- Copilot
- Antigravity

정책:

- `priority-fallback`: 1번 계정 소진/기준 이하 → 다음 사용 가능한 계정
- `max-remaining`: 잔여량이 가장 높은 계정
- `fixed-primary`: 기본 계정 고정

오래된 cache, 최근 live 조회 실패, 명시적 limit-reached, 알 수 없는 quota는 자동 선택에서 제외한다.

터미널 런처:

- `codex-auto.cmd`
- `claude-auto.cmd`
- `grok-auto.cmd`
- `cursor-auto.cmd`
- `copilot-auto.cmd`
- `antigravity-auto.cmd`

Smart Routing은 **새로 실행하는 CLI 프로세스**에 적용한다. 이미 실행 중인 CLI/웹/데스크톱 세션의 인증 파일을 중간에 교체하지 않는다.

OpenRouter의 기존 localhost router는 별도로 API 요청 단위 key failover를 계속 제공한다.

## Copilot CLI

최신 GitHub Copilot CLI는 legacy `gh copilot`이 아닌 standalone `copilot` 실행 파일을 사용한다.

추가 Copilot 계정은 GitHub CLI의 격리 config에서 OAuth를 얻고, 선택된 CLI 프로세스에만 `COPILOT_GITHUB_TOKEN`을 주입한다. 토큰은 settings/usage cache/command line에 기록하지 않는다.

## Codex reset ticket

기본 계정의 `Codex 한도 자동 리셋`은 기존 opt-in 정책을 유지한다.

추가 Codex 계정은 프로필별 별도 토글을 제공하며 명시적으로 켠 프로필만 banked reset ticket을 자동 사용한다. 모든 계정에 전역 토글을 일괄 적용하지 않는다.

기존 안전 조건을 유지한다.

- 서버가 실제 `rate_limit_reached`를 보고한 경우만 시도
- 사용 가능한 banked reset ticket 필요
- 먼저 만료되는 ticket 선택
- account/fingerprint별 idempotency guard
- stale/반올림 0%만으로 ticket 사용 금지

## CLI 버전/업데이트

연결 카드에서 설치된 CLI 버전을 표시하고 최신 버전을 확인할 수 있는 공급자는 업데이트 여부도 표시한다.

업데이트 버튼은 확인된 공식 updater/install 경로가 있는 설치 방식에만 노출한다.

- Codex — 공식 installer 또는 npm 설치 방식
- Claude — `claude update`
- Grok — `grok update --check` / `grok update`
- Cursor — `cursor-agent update`
- Copilot — standalone `copilot`; npm 또는 확인 가능한 WinGet 설치 방식
- Antigravity — 공식 Windows installer

설치 방식을 안전하게 판별할 수 없으면 최신 버전이 보여도 임의의 패키지 관리자를 실행하지 않는다.
