# v1.0.25 — Minimal account connection hub

## 목표

설정 화면에서 자격증명 파일 위치, config directory, PAT, cookie, API Key를 먼저 이해해야 했던 등록 흐름을 없애고, 각 공급자를 **상태 + 로그인 + 계정 추가** 중심으로 연결한다.

기존의 고급 수동 설정은 삭제하지 않는다. 자동 로그인 재사용이 불가능하거나 문제 진단이 필요한 경우에만 `고급 설정`을 열어 사용한다.

## 기본 설정 구조

설정을 열면 기본적으로 세 영역만 보인다.

1. **계정 연결**
   - 공급자별 연결 상태
   - `로그인` / `다시 로그인`
   - 다계정 지원 공급자의 `+ 계정`
   - `상태 새로고침`
2. **기본**
   - 항상 위에
   - 시작 시 실행
   - 빈 계정 숨기기
3. **고급 설정** (기본 닫힘)
   - 표시 방식/투명도/밀도/토큰 영역 높이
   - 화면 가장자리 동작
   - raw 다계정 config path editor
   - Smart Routing
   - 자동화/동기화
   - OpenRouter profile/API Key/Management Key/router 세부값
   - GitHub PAT/Cursor cookie 수동 fallback

기존 DOM element를 복제하지 않고 위치만 이동하므로 기존 이벤트 처리와 settings persistence 경로를 유지한다.

## 공급자 로그인

### Codex

- 기본 계정: `codex login`
- `+ 계정`: 앱이 `%APPDATA%/how-much-is-tokens/profiles/codex/account-N` 경로를 만들고 해당 프로세스의 `CODEX_HOME`으로 지정한 뒤 `codex login` 실행
- `auth.json`을 앱이 복사/교체하지 않음

### Claude

- 기본 계정: `claude auth login`
- `+ 계정`: 관리형 `account-N` 디렉터리를 `CLAUDE_CONFIG_DIR`로 지정한 뒤 공식 로그인 실행
- `.credentials.json`을 앱이 복사/교체하지 않음

### Grok

- 기본 계정: `grok login`
- `+ 계정`: 관리형 `account-N` 디렉터리를 `GROK_HOME`으로 지정한 뒤 공식 로그인 실행
- auth file을 앱이 복사/교체하지 않음

### Cursor

- `cursor-agent login`을 우선 사용하고 설치 형태에 따라 `agent login`을 fallback으로 탐색
- 기존 Cursor 앱/CLI 인증 저장소를 provider가 읽음
- 자동 탐색이 불가능할 때만 고급 설정의 Cursor cookie를 사용

### Grok Bot

- 별도 자격증명 저장소를 만들지 않음
- 현재 Grok Bot usage provider는 Cursor 인증을 공유하므로 Grok Bot 카드의 로그인도 Cursor 로그인 흐름으로 연결

### Copilot

- `gh auth login`으로 GitHub OAuth 로그인
- 기존 Copilot/VS Code/GitHub hosts 파일을 우선 사용하고, 파일에 토큰이 없으면 `gh auth token`을 실행해 GitHub CLI credential manager의 토큰을 메모리에서만 재사용
- 앱 설정의 PAT는 고급 fallback으로 유지

### Antigravity

- `agy`를 실행해 Antigravity CLI의 Google 로그인 흐름을 시작
- 앱은 Antigravity 자격증명 원문을 저장하지 않음

### OpenRouter

- 수동 API Key 붙여넣기 대신 공식 OAuth PKCE를 기본 연결로 사용
- callback server는 `127.0.0.1`의 임의 포트 및 CSPRNG nonce path에만 bind
- authorization code와 PKCE verifier를 `https://openrouter.ai/api/v1/auth/keys`로 교환
- exchange와 발급 API Key는 **main process에서만** 처리
- 발급된 API Key는 기존 `saveOpenRouterProfileSecrets` 경로를 통해 Electron safeStorage 암호문으로 즉시 저장
- preload/page에는 raw API Key를 반환하지 않음
- `+ 계정`은 새 OpenRouter profile metadata를 자동 생성한 뒤 동일 OAuth 흐름으로 연결

## 다계정 원칙

- Codex/Claude/Grok은 기본 로그인 디렉터리와 추가 로그인 디렉터리를 완전히 분리
- 인증 파일 자체를 복사하거나 파일명을 바꿔 전환하지 않음
- 추가 계정 경로는 앱 관리 영역에서 충돌 없는 `account-N`을 자동 선택
- 기존 사용자가 직접 등록한 profile path는 그대로 유지하고 고급 설정에서 편집 가능

## 보안 경계

- 공급자 CLI 명령과 인자는 코드에 고정하고 사용자 입력을 shell command에 연결하지 않음
- profile config path는 command argument가 아니라 환경변수로만 전달
- OpenRouter OAuth callback은 loopback-only
- OpenRouter API Key는 renderer/preload IPC 응답에 포함하지 않음
- Copilot `gh auth token` 결과는 usage request 메모리에서만 사용하고 settings에 기록하지 않음
- 기존 v1.0.24 OpenRouter request router의 loopback/fail-closed/no-replay 정책은 변경하지 않음

## 자동 검증

- 공급자별 login command mapping
- Cursor binary 우선순위
- shell command/path/argument validation
- Codex/Claude/Grok 관리형 config root와 collision avoidance
- profile login에서 `CODEX_HOME` 등 provider-specific environment 사용
- OpenRouter PKCE verifier/challenge, auth URL, loopback callback, code exchange
- OpenRouter exchange가 preload가 아니라 main process에만 존재하는지 정적 경계
- Copilot GitHub CLI credential-manager fallback
- 8개 provider connection card 렌더링
- 기본 3개 옵션만 expanded 상태인지 확인
- raw profile editor/API Key/표시 세부값이 고급 설정 안에 있는지 확인
- 기존 edge/titlebar layout smoke
- 전체 기존 regression + Leerness gate + Windows DPAPI smoke
