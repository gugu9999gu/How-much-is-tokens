# How much is tokens v1.0.24

## OpenRouter 다중 API Key 프로필

OpenRouter API Key를 여러 개 등록해 각 프로필의 사용량/크레딧 상태를 따로 확인할 수 있습니다.

- 프로필별 API Key 및 선택적 Management Key
- 우선순위와 활성/비활성 설정
- 기존 단일 OpenRouter Key는 `default` 프로필로 계속 사용할 수 있음
- 키 원문은 Windows의 Electron safeStorage를 통해 암호화 저장
- 설정 파일에는 키 원문을 기록하지 않음

## localhost OpenAI-compatible Router

OpenAI-compatible 클라이언트가 하나의 로컬 endpoint를 사용하면서 등록된 OpenRouter Key 사이에서 자동으로 선택/failover할 수 있습니다.

기본 Base URL:

```text
http://127.0.0.1:43123/v1
```

클라이언트의 API Key 자리에는 OpenRouter 원본 Key가 아니라 위젯의 **로컬 Bearer 토큰 복사** 버튼으로 받은 별도 토큰을 사용하세요.

### 선택 정책

- **우선순위 fallback**: 우선순위가 높은 Key부터 사용하고 사용할 수 없으면 다음 Key로 전환
- **잔여량 최대**: 위젯이 확인한 잔여량이 높은 Key를 우선 선택

### 자동 failover

응답이 시작되기 전에 OpenRouter가 `401`, `402`, `403`, `429`처럼 Key/계정이 현재 요청을 처리할 수 없음을 명시하면 해당 Key를 cooldown하고 다음 Key를 시도합니다. 모든 Key를 사용할 수 없으면 명시적으로 `503`을 반환합니다.

네트워크 단절은 요청이 이미 처리됐는지 확실하지 않을 수 있으므로 더 보수적으로 동작합니다.

- `GET`/`HEAD`/`OPTIONS`: 다음 Key로 재시도 가능
- `POST` 등 비멱등 요청: 다른 Key로 자동 재전송하지 않고 `502` 반환

이렇게 하면 연결 오류 상황에서도 중복 completion, 중복 과금 또는 중복 tool side effect를 줄일 수 있습니다.

## 보안 경계

- Router는 **127.0.0.1에만** 연결되며 LAN/WAN에 공개되지 않음
- 로컬 Bearer 토큰과 OpenRouter 원본 Key는 별도로 관리
- 로컬 클라이언트가 보낸 API Key/쿠키 계열 인증 헤더는 OpenRouter upstream으로 전달하지 않음
- Authorization, API Key, 요청 본문을 로그에 기록하지 않음
- 스트리밍 응답이 시작된 뒤 실패하더라도 다른 Key로 같은 요청을 자동 재전송하지 않음

## 검증

이번 버전은 다음 항목을 자동 테스트합니다.

- 프로필별 secure secret 격리 및 기존 단일 Key 호환
- Windows DPAPI/safeStorage 암호화 저장
- loopback-only bind
- 429 cooldown 및 Key failover
- 잔여량 기반 선택
- 비멱등 POST network failure no-replay
- 멱등 GET network failover
- 모든 Key 사용 불가 시 503 fail-closed
- 스트리밍 시작 후 요청 replay 방지
- credential header upstream 차단
- Electron renderer smoke 및 Leerness security gate
