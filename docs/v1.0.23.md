# v1.0.23 — Smart Routing

v1.0.23은 v1.0.22의 격리 다계정 표시를 실제 **새 CLI 실행 계정 선택**으로 확장합니다.

## 핵심 원칙

Smart Routing은 이미 실행 중인 ChatGPT/Codex/Claude/Grok 세션의 인증을 바꾸지 않습니다.

새 CLI를 실행할 때만 선택된 프로필의 환경을 주입합니다.

- Codex: `CODEX_HOME`
- Claude Code: `CLAUDE_CONFIG_DIR`
- Grok / Grok Build: `GROK_HOME`

인증 파일을 복사하거나 기본 프로필의 token 파일을 덮어쓰지 않습니다.

## 지원 정책

provider별로 독립 설정합니다.

### `1번 소진 → 다음 계정`

`priority-fallback`

계정 순서는 다음과 같습니다.

1. 기본 계정
2. 다계정 프로필에 등록한 첫 번째 계정
3. 두 번째 추가 계정
4. 이후 등록 순서

현재 잔여량이 `전환 기준`보다 큰 첫 번째 계정을 선택합니다.

예:

```text
Codex · 기본 계정   0%
Codex · GPT 2번    43%
Codex · GPT 3번    81%

→ GPT 2번 실행
```

### `잔여량 가장 많은 계정`

`max-remaining`

전환 기준보다 높은 계정 중 대표 quota 잔여율이 가장 큰 계정을 선택합니다.

```text
Codex · 기본 계정  26%
Codex · GPT 2번    61%
Codex · GPT 3번    44%

→ GPT 2번 실행
```

동률이면 계정 등록 순서가 빠른 쪽을 선택합니다.

### `기본 계정 고정`

`fixed-primary`

자동 잔여량 판단 없이 기본 계정을 실행합니다. 고정 정책은 사용자 명시 선택이므로 `전환 기준`을 적용하지 않습니다.

## 안전 조건

`priority-fallback` 및 `max-remaining`은 다음 account를 자동 선택 대상에서 제외합니다.

- `status !== ok`
- stale usage snapshot
- 서버/Provider 결과가 명시적으로 `한도 도달`을 나타냄
- 대표 `remainingPct`가 없어서 사용 가능 여부를 판단할 수 없음
- `remainingPct <= 전환 기준`

따라서 네트워크 오류 뒤 다른 계정의 오래된 값만 보고 자동 전환하지 않습니다.

모든 계정이 제외되면 임의 계정을 실행하지 않고 오류를 반환합니다.

## 위젯에서 실행

설정 화면에 **Smart Routing** 영역이 추가됩니다.

Provider별로:

- Smart Routing ON/OFF
- 선택 정책
- 전환 기준 `%`
- `Codex 스마트 실행`
- `Claude 스마트 실행`
- `Grok 스마트 실행`

을 설정할 수 있습니다.

스마트 실행 버튼은 먼저 위젯 사용량을 새로고침한 뒤 최신 결과로 계정을 선택합니다.

선택 후 새 Windows 콘솔에서 해당 CLI를 실행하며, 실행 결과에 선택된 계정 이름과 잔여율을 표시합니다.

## 터미널용 `*-auto.cmd`

설정 → Smart Routing → **터미널 런처 설치**를 누르면 다음 폴더를 생성합니다.

```text
%APPDATA%\how-much-is-tokens\router-bin
```

생성 파일:

```text
codex-auto.cmd
claude-auto.cmd
grok-auto.cmd
how-tokens-route.ps1
README.txt
```

이 폴더를 사용자 `PATH`에 추가하면 일반 터미널에서 다음처럼 실행할 수 있습니다.

```powershell
codex-auto
claude-auto
grok-auto
```

`how-tokens-route.ps1`은 위젯이 저장한 다음 파일만 읽습니다.

```text
%APPDATA%\how-much-is-tokens\settings.json
%APPDATA%\how-much-is-tokens\usage-cache.json
```

`priority-fallback` / `max-remaining`에서는 cache가 너무 오래되면 자동 선택하지 않습니다. 허용 cache age는 최소 2분이며 현재 새로고침 간격의 약 3배를 상한 판단 기준으로 사용합니다.

따라서 터미널 런처를 사용할 때는 위젯을 실행해 두거나 직전에 새로고침하는 것이 좋습니다.

`fixed-primary`는 quota cache 없이도 기본 프로필을 실행할 수 있습니다.

## Codex reset ticket과의 관계

기존 `Codex 한도 자동 리셋`은 별도 기능이며 기본값 OFF입니다.

위젯의 `Codex 스마트 실행`은 실행 전 `refresh`를 수행하므로, 사용자가 Codex 자동 리셋을 이미 켰고 공식 app-server가 실제 `rate_limit_reached`를 반환한다면 기존 v1.0.21 안전 정책에 따라 reset ticket이 먼저 사용될 수 있습니다.

리셋 성공 후 기본 계정 quota가 회복되면 `priority-fallback` 정책은 기본 계정을 계속 선택할 수 있습니다.

추가 Codex 프로필의 reset ticket 자동 사용은 여전히 하지 않습니다.

## 현재 범위

v1.0.23은 **CLI session launcher routing**입니다.

포함:

- Codex / Claude / Grok 새 실행 계정 자동 선택
- priority fallback
- max remaining
- fixed primary
- provider별 threshold
- 위젯 실행 버튼
- 터미널용 standalone launcher

포함하지 않음:

- 이미 실행 중인 CLI 세션을 중간에 다른 계정으로 전환
- ChatGPT Desktop/Web 세션 강제 account switch
- 한 모델 요청 단위의 transparent proxy routing
- Cursor/Copilot/OpenRouter 다계정 credential router

요청 단위의 API Smart Routing은 별도의 localhost proxy 계층이 필요한 다음 단계입니다.
